# Release checklist

Legend: **Done** = in the repository now · **You** = needs your account or a decision.

## 1. App build

| Item | Status | Notes |
| :--- | :--- | :--- |
| Package name `dev.atreyakamat.tracknow` | Done | `apps/mobile/app.json` |
| App icon, adaptive icon (foreground, background, monochrome), splash | Done | `apps/mobile/assets/images/`, regenerated by `scripts/render_brand.cjs` |
| Version 1.0.0, runtime version policy `appVersion` | Done | Bump `version` in `app.json` for every native change; EAS manages `versionCode` when `autoIncrement` is on |
| Production build profile | Done | `apps/mobile/eas.json` → `production` (Android App Bundle) |
| Environment variables on EAS (`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`) | Done for preview | **You:** run `npx eas-cli env:push production --path .env` once before the first production build, or the app starts without a backend |

| Over-the-air updates | Done | `eas update --branch production --environment production` ships JS-only changes after release |
| Release build | You | `cd apps/mobile && npx eas-cli build --profile production --platform android` |

## 4. Before pressing Publish

| Item | Status | Notes |
| :--- | :--- | :--- |
| Email code template contains `{{ .Token }}` | You | Supabase → Authentication → Email Templates (Magic Link and Confirm signup) |
| Custom SMTP for sign-in emails | You | The built-in sender allows only a few emails an hour; a store launch will exceed it |
| Internal testing install on a real phone | You | Check sign-in, add an item, complete it, a reminder notification, the home-screen widget |
| Closed test: 12 testers for 14 days | You | Required by Google for new personal developer accounts before production access |
| Notifications permission prompt reads well | Done | Asked on first launch inside the app; reminders work without a network |
| Crash-free start without network | Done | Offline screen with Retry; cached lists |

## 5. After release

- Reply to every review in the first month.
- Ship fixes over the air (`eas update`) where possible; rebuild only for native changes.
- Update `listing/release-notes.txt` for each store release (500 characters max).
